# AnyHTML — هر ورودی ← یک فایل HTML تکی (آفلاین، مناسب آیفون)

## راه‌اندازی (یک‌بار)
1. همه فایل‌های این پوشه (بدون .github) را در ریپو آپلود کنید و فایل workflow را طبق راهنما با «Create new file» بسازید.
2. Settings → Pages: منبع = همین شاخه / root.
3. Settings → Actions → General → Workflow permissions = **Read and write**.
4. یک توکن Fine-grained بسازید (فقط همین ریپو): **Contents: Read & write** و **Actions: Read**.
5. صفحه `https://USERNAME.github.io/REPO/` را باز کنید → تنظیمات → ریپو و توکن → ذخیره. (در Safari: Share → Add to Home Screen)

## استفاده
فایل (زیپ پروژه یا هر فایل دیگر) را انتخاب کنید ← «تبدیل به HTML». چند دقیقه بعد دکمه باز کردن / دانلود / اشتراک‌گذاری ظاهر می‌شود.
بدون توکن هم می‌شود: فایل را از وب GitHub در پوشه `inbox/` آپلود کنید، یا Actions → anyhtml → Run workflow با لینک مستقیم زیپ. خروجی در `outputs/` می‌آید.

روی کامپیوتر (ویندوز، مک، لینوکس؛ فقط Node 18+ لازم است):
```
npm install
node anyhtml.mjs project.zip out.html
```
در ویندوز: فایل زیپ را روی `convert-windows.bat` بکشید و رها کنید.

## تبدیل همه‌ی ریپوهای گیت‌هاب
```
set GITHUB_TOKEN=github_pat_...
node all-repos.mjs
```
بدون توکن: `node all-repos.mjs --user USERNAME` (فقط عمومی‌ها). در ویندوز `all-repos-windows.bat` را دوبار کلیک کنید.
گزینه‌ها: `--only a,b` `--skip a,b` `--forks` `--archived` `--limit N` `--force` `--out DIR`
خروجی: پوشه `all-out/` شامل یک HTML برای هر ریپو و `index.html` برای فهرست. هر ریپویی که خراب شود رد می‌شود و بقیه ادامه می‌دهند.
توکن Fine-grained برای ریپوهای خصوصی: Contents = Read-only روی همه‌ی ریپوها.

## موتور چه کار می‌کند (به ترتیب، اولین موفق برنده است)
| ورودی | کار |
|---|---|
| `package.json` با build (Vite/React/Vue/Svelte/…) | نصب وابستگی‌ها، بیلد، HTML تکی (Vite: تک‌فایل واقعی)، جاسازی عکس/فونت/CSS/فونت‌های CDN |
| سایت HTML/CSS/JS (چندصفحه‌ای هم) | جاسازی همه‌چیز؛ لینک‌های بین صفحه‌ها داخل همان فایل کار می‌کنند |
| پروژه با سرور (Node `start`/`dev`، Flask/FastAPI/Django، PHP) | نصب، اجرا، خزیدن در صفحه‌ها با Chromium و ذخیره‌ی تصویر ثابتِ هر صفحه |
| هر چیز دیگر (md, csv, json, کد، pdf, عکس…) | مرورگر فایل داخل HTML |

اگر یک روش شکست بخورد، خودکار روش بعدی امتحان می‌شود؛ خروجی همیشه یک HTML است و گزارش در `outputs/<name>.report.txt` می‌ماند.

## محدودیت‌های صادقانه
- پروژه‌ی سروری فقط «عکس ثابت» از صفحه‌هاست: اسکریپت‌ها حذف می‌شوند، فرم و درخواست به بک‌اند و صفحه‌های پشت لاگین کار نمی‌کنند.
- اسکریپت پایتون/ابزار خط فرمان (بدون وب) اجرا نمی‌شود؛ کدش در مرورگر فایل دیده می‌شود.
- سایت‌های وابسته به API خارجی/کلید (مثل Gemini) آفلاین پاسخ نمی‌گیرند.
- ورودی‌ها و خروجی‌ها در ریپو commit می‌شوند؛ در ریپوی عمومی برای همه قابل دیدن‌اند.
- پروژه‌ی ناقص (مثلاً فقط index.html که از state.js import می‌کند و آن فایل‌ها نیستند) تبدیل نمی‌شود؛ ابزار به‌جای صفحه‌ی خالی، مرورگر فایل می‌دهد و علت را در گزارش می‌نویسد.
- اجرای سرور در ویندوز نیاز به Node/Python/PHP نصب‌شده دارد؛ تبدیل ریپوهای بیلدی و استاتیک فقط Node می‌خواهد.
- روی GitHub واقعی و ویندوز واقعی هنوز اجرا نشده؛ موتور روی لینوکس و صفحه آپلود با API ساختگی تست شده‌اند.
